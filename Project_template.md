### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут управлять отоплением
- Система поддерживает возможность подключения прибора с помощью выезда специалиста
- Управление приборами происходит напрямую с сервера

**Мониторинг температуры:**

- Пользователи могут поддерживать температуру в доме.
- Система поддерживает возможность подключения прибора с помощью выезда специалиста
- Управление приборами происходит напрямую с сервера
- Данные о температуре получаются через запрос от сервера к датчику температуры

### 2. Анализ архитектуры монолитного приложения

### 3. Определение доменов и границы контекстов

Домены as is:
1. Управление отоплением. Граничцы контекста: Передача команд управления приборам по соответствию темпертуры заданным критериям.
2. Мониторинг температуры. Границы контекста: Получить данные о температуре с датчиков, определить статус темпеературы.

Домены to be:
1. Управление пользователями. Границы контекста: Регистрация, роли, управление профилем, аутентификация и авторизация
2. Управление приборами. Границы контекста: Подключение устройств, хранение метаданных, REST API управления устройствами
3. Управление видео наблюдения. Границы контекста: Настройка камер, сжатие и сохранение видео в облачном хранилище
4. Управление сценариями использования приборов. Границы контекста: Создание и выполнение правил, интеграция с сервисом погоды
5. Телеметрия. Границы контекста: Сбор данных с устройств, аналитика, хранение истории.


### **4. Проблемы монолитного решения**

- Каждое подключение прибора необходимо сопроводить выездом специалиста, что не допустимо при планах по масштабированию пристутствия в регионах территории рФ
- Недостаточная функциональность для соответствия требвоаниям тендера/заказа на создание экосистемы умных поселков
- Решение в текущей архитектуре не масштабируемо
