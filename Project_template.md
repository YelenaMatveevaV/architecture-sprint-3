### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут управлять отоплением
- Система поддерживает возможность подключения прибора с помощью выезда специалиста
- Управление приборами происходит напрямую с сервера

**Мониторинг температуры:**

- Пользователи могут поддерживать температуру в доме.
- Система поддерживает возможность подключения прибора с помощью выезда специалиста
- Управление приборами происходит напрямую с сервера
- Данные о температуре получаются через запрос от сервера к датчику температуры

### 3. Определение доменов и границы контекстов

Домены as is:
1. Управление отоплением. Граничцы контекста: Передача команд управления приборам по соответствию темпертуры заданным критериям.
2. Мониторинг температуры. Границы контекста: Получить данные о температуре с датчиков, определить статус темпеературы.

Домены to be:
1. Управление пользователями. Границы контекста: Регистрация, роли, управление профилем, аутентификация и авторизация
2. Управление приборами. Границы контекста: Подключение устройств, хранение метаданных, REST API управления устройствами
3. Управление видео наблюдения. Границы контекста: Настройка камер, сжатие и сохранение видео в облачном хранилище
4. Управление сценариями использования приборов. Границы контекста: Создание и выполнение правил, интеграция с сервисом погоды
5. Телеметрия. Границы контекста: Сбор данных с устройств, аналитика, хранение истории.


### **4. Проблемы монолитного решения**

- Каждое подключение прибора необходимо сопроводить выездом специалиста, что не допустимо при планах по масштабированию пристутствия в регионах территории рФ
- Недостаточная функциональность для соответствия требвоаниям тендера/заказа на создание экосистемы умных поселков
- Решение в текущей архитектуре не масштабируемо

# Задание 3. Разработка ER-диаграммы

3.1 Идентификация сущностей
Роли пользователей - Role,
Пользователь — User,
Тип устройства — DeviceType,
Устройство — Device,
Место устройства - Place_Device,
Место - Place,
Телеметрия — TelemetryData.
Уведомления пользователя - Notification
История изменений - AuditLog
Команды управления прибором - Event
Сценарий управления приборами - ScenarioExecution

3.2 Определение атрибутов
3.2.1. Роли пользователей - Role:
  id - Идентификатор роли
  name - наименование роли
  permissions - разрешения роли

3.2.2 Пользователь — User:
  id - Идентификатор пользователя
  email - электронный адрес пользователя
  password_hash - хэш пароля
  role_id - идентификатор роли 
  created_at - дата создания пользователя

3.2.3 Тип устройства — DeviceType:
  id - идентификатор типа устройства
  type - тип устройства
  protocol - протокол типа устройства
  created_at - дата создания типа

3.2.4 Устройство — Device:
  id - идентификатор устройства
  type_id - идентификатор типа устройства
  status - статус устройства
  vendor - производитель устройства
  created_at - дата создания устройства

3.2.5 Место устройства - Place_Device:
  place_id - идентификатор места
  device_id - идентификатор устройства
  date_from - дата установки
  date_to - дата демонтажа

3.2.6 Место - Place:
  id - идентификатор места
  user_id - идентификатор пользователя
  name - наименование места
  square - площадь места
  height - высота места
  created_at - дата создания

3.2.7 Телеметрия — TelemetryData:
  id - идентификатор сведений
  device_id - идентификатор устройства
  metric_type - тип измерения
  value - измерения
  timestamp - таймстамп снятия измерений

3.2.8 Уведомления пользователя - Notification:
  id - идентификатор уведомления
  user_id - идентификатор пользователя
  type - тип уведомления
  content - текст уведомления
  status - статус отправки уведомления
  created_at - дата создания

3.2.9 История изменений - AuditLog:
  id - идентификатор изменения
  user_id - идентификатор пользователя
  action - выполненное действие
  target_entity - измененный объект
  timestamp - таймстамп внесения изменения
  details - сведения о том как было и как стало после внесенного изменения

3.2.10 Команды управления прибором - Event:
  id - идентификатор
  type - тип события
  device_id - идентификатор устройства
  user_id - идентификатор пользователя
  timestamp - таймстапм события
  payload - команда прибора

3.2.11 Сценарий управления приборами - ScenarioExecution:
  id - идентификатор сценария
  scenario_id - идентификатор сценария в БД Mongo
  trigger_event_id - идентификатор команды
  status - статус выполнения команды
  start_time - дата начала выполнения команды
  end_time - дата завершения выполнения команды

3.3 Описание связей
Пользователь — Роль: Каждый пользовател имеет одну роль, несколько пользователей могут иметь одну роль.
Пользователь - Место: Каждый пользователь может быть связан с несколькими местами, каждое место связано только с одним пользователем.
Устройство - Телеметрия: Каждое устройство может генерировать множество записей телеметрии, сведения телеметрии связаны с одним устройством.
Устройство - Тип устройства: Каждое устройство может быть только одного типа, каждый тип может быть связан с несколькими устройствами;
Устройство - Команды управления прибором: Каждое устройство может иметь множество команд к программированию в сценарии.
Пользователь - Команды управления прибором: Каждая команда связана с пользователем, создавшим ее.
Место - Место устройства: Каждое место может быть использовано для установки нескольких устройств.
Устройство - Место устройства: Каждое устройство в один период времени может быть связано с одним местом установки, устройство может быть перемещено в другое место установки.
Команды управления прибором - Сценарий управления приборами: Каждая команда по управлению прибором может быть включена в несколько сценарием управления приборами.
Пользователь — Уведомления пользователя: Каждый пользователь может получить множество уведомлений разных типов, каждое уведомление отправляется только одному пользователю.
Пользователь — История изменений: Все изменения, выполняемые пользователем логируются, каждое изменение связано с пользователем, по каждому пользователю хранится множество записей истории действий.
